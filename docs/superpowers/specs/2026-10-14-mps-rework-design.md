## 1. 背景与目标

aps-hap 现有业务为通用 SMT 离散制造排产（明道云为主数据平台 + PostgreSQL 本地库 + OR-Tools/GA 求解器）。业务已根本改变为**封测中心成套工艺核算与周计划排产**（MPS V1.6/V1.7），且数据要求"明道云与本地均可以使用"，不再以明道云为唯一数据底座。

目标：
1. 以 aps-hap 为技术骨架（FastAPI + React/TS/AntD + 求解器框架 + 同步机制），业务按 MPS 重做；
2. 数据层支持双形态：本地 SQLite（单机零运维）/ PostgreSQL（服务器多用户）；明道云同步可整体关闭；
3. 明道云表单 ID/字段配置化（专用设置页：填表单 ID → 读取表单 → 自动匹配 → 手动调整个别字段），密钥加密存储、永不回显；
4. 核算内核 1:1 移植 mps-web（与官方算例逐项对齐）；排产内核以 GA 为核心（OR-Tools 可选、确定性基准保留）；
5. 保留报工/执行类模块的代码与页面（冻结，不接入新模型，二期适配）；旧计划类表/页面由新模型替换，旧数据可删。

## 3. 总体架构

```
┌────────────── 前端（React 18 + TS + Vite + AntD + ECharts）──────────────┐
│ ① 工单管理 ② 排产结果 ③ 工序产能负荷 ④ 甘特图 ⑤ 日任务看板 ⑥ 基础数据       │
│ ⑦ 明道云映射设置   执行类页面（报工/工序进度/工时，冻结保留）               │
└──────────────────────────────────┬──────────────────────────────────────┘
                                   │ REST（沿用现有 client/apiKey 鉴权）
┌──────────────────────────────────▼──────────────────────────────────────┐
│ FastAPI 后端                                                             │
│  ├─ 核算引擎（确定性，1:1 移植 mps-web engine.js）                         │
│  ├─ 排产内核                                                             │
│  │   ├─ 求解层（可插拔 BaseSolver）：GA(DEAP,默认) / CP-SAT(可选) / 确定性   │
│  │   └─ 解码执行层（1:1 移植 mps-web schedule.js：按日产能账本分配、        │
│  │      工序串行、齐套门槛、setup 天数、分流、超载判定）                     │
│  ├─ 优先级引擎（1:1 移植 priority.js）+ 策略（1:1 移植 strategy.js）        │
│  ├─ 看板/甘特/周负荷（1:1 移植 kanban.js / 甘特数据）                      │
│  ├─ 同步引擎（通用化：映射来自数据库，去硬编码 TABLE_HAP_MAP）             │
│  └─ HAP 客户端（沿用 hap/client.py，密钥加密读取）                         │
├──────────────────────────────────────────────────────────────────────────┤
│ 数据层：SQLAlchemy 2.0 异步，可移植类型；SQLite(aiosqlite) / PostgreSQL     │
└──────────────────────────────────────────────────────────────────────────┘
```

求解语义（D11）：
- GA 是"序列/方案搜索器"，mps-web 的分配规则是"解码器"——所有业务逻辑均在，GA 仅在规则之上寻优；
- GA 无解/关闭时退化为确定性基准（输出与 mps-web 一致，用于验收）；
- 适应度 = mps-web 目标函数（延期/换型/均衡/完工期加权）；硬约束（产能不超、齐套、串行）= 罚函数或修复；种群/代数/权重/随机种子可配置；
- 策略层（priority/due/util/setup/bottleneck）保留为 GA 初始种群与权重预设；CP-SAT 保留为可选模式（非验收基准）。

## 4. 数据模型（新 MPS 模型）

统一出箱字段 `hap_row_id / sync_status / synced_at`，以复用同步机制。

| 表 | 关键字段 | 说明 |
|---|---|---|
| `process_master` | 级别\|工序\|模式(PK)、基准周期、一次装配/检验合格率(存档)、综合成品率、单工位日产能、工位数、均值/峰值通量、核算单位、特征参数名、分流阈值、周期调节、备注 | 工序主数据（~28 行），来自 V1.7 |
| `process_set` | 工艺代号(PK，含版本)、产品形态、封装架构、负责人、单件/加急/批量周期×口径、成品率、放量比、分部件规则(前置/平行+周期)、爬坡时间、瓶颈、路线文本、状态 | 成套工艺（~24 套 D01~C11） |
| `process_route` | 工艺代号+序号、工序原文名、规范工序名、适用级别、周期、一次检验合格率、综合成品率、核算特征、折算系数、触发条件 | 工艺路线（~133 行） |
| `order` | 订单号(唯一)、产品型号、工艺代号、订单类型(常规/加急)、首单/复线/变更首件、水汽要求、计划批量、需求日期、物料齐套时间、排产优先级(数字)+优先级引擎字段(评分/级别/来源/置顶/拖拽序)、状态、BOM 特征(13+2 项)、结果回写字段(投料量/成品率/放量比/单件周期/采用通量/瓶颈工序/批量周期/爬坡/交付周期/最晚投料日/排产开始完成日/交期判定/gap) | 产品工单（B 口径特征） |
| `order_operation` | 工单ID、工序序号、级别、规范工序名、模式、数量(只/特征量)、依赖前道ID(工序间约束)、来源(自动分解/手工追加)、备注 | **工序级需求**：自动由路线分解；支持手工增删（返工/试制=插工序需求） |
| `system_param` | key/value/label/分组 | 系统参数：week_days=6、peak_factor=1.1、use_peak、exclude_braze_yield、cf_db_1/2/3、cf_wb_1/2/3、vapor_cap_cut、订单缓冲、参考批量、GA 参数、定时同步间隔 等 |
| `schedule_batches` | 批次号、基准日期、求解模式、策略、参数快照、KPI | 排产批次 |
| `schedule_allocations` | 批次ID、工单ID、工序级需求ID、资源(级别\|工序\|模式)、分配日期、数量（起止日/瓶颈由分配派生） | 排产分配明细（支持历史/对比/推送） |
| `priority_log` / `priority_batch` | 沿用 mps-web：变更审计、批量撤销快照 | 优先级审计 |
| `hap_connection` | base_url、app_id、app_key_enc、sign_enc、更新时间（单行） | 加密连接配置 |
| `hap_mapping` | 实体 key、表单ID(ws_id)、同步方向、启用状态 | 实体→表单 |
| `hap_field_mapping` | 实体 key、本地字段、表单控件ID、表单字段名、类型、选项映射JSON、关联配置、自动匹配置信度、手工覆盖标记 | 字段映射 |

关系：`process_set 1—N process_route`；`process_route N—1 process_master`（级别+规范名+模式）；`order 1—N order_operation`；`order_operation 1—N schedule_allocations`。

核算口径（1:1 移植，全部参数化）：
- T单件 = Σ工序周期 + 前置分部件（平行分部件不计）；封盖类无水汽 2→1 天
- T加急 = max(T − ΔT, 1)，ΔT：T≤5→1 / 6~10→2 / >10→3
- Y = Π综合成品率（组件钎焊按 `exclude_braze_yield` 开关）；放量比 = 1/Y；投料量 = ⌈批量×放量比⌉（产出校核迭代）
- 产品级通量 = 基准通量(按模式) × 折算系数(Y_die/Y_wire 查表) ÷ 单只特征用量；瓶颈 = 取小
- T批量 = T单件 + max(0, 批量项)，取整口径按 `round_mode` 参数；爬坡按 `ramp_trigger` 参数（事件触发；爬坡期通量 min(1, t/T) 折算）
- 交付周期 = T批量 + 爬坡 + 订单缓冲；最晚投料日 = 交期 − 交付周期
- 周负荷 = Σ(投料量×特征用量)；周可用 = 通量×周工作天数；>100% 超载 / ≥85% 偏紧 / <85% 正常
- 瓶颈占用(天) = ⌈投料量 ÷ 采用通量⌉

## 5. 双数据库（SQLite / PostgreSQL）

- SQLAlchemy 2.0 异步 + 可移植类型（`Uuid` 字符串、`JSON`、`DateTime`），不使用 PG 专有类型；
- 服务器：PostgreSQL + Alembic 迁移链；本地：SQLite(aiosqlite) 单文件 + 启动 `create_all` + schema 版本校验；
- 模式由 `DATABASE_URL` 决定；`DISABLE_HAP_SYNC=1` 或未配置映射时自动纯本地；
- 基础数据来源：内置种子（由 mps-web seed.json 转换）+ Excel 导入（兼容 V1.7 清单格式）+ 明道云拉取。

## 6. 明道云映射设置页与密钥安全（重点）

配置流程：
1. 连接配置：录入 Base URL、App ID、AppKey、Sign → 后端 Fernet 加密存储；页面此后仅显示"已配置 + 更新时间"，**永不回显明文**；修改需重新输入；
2. 实体映射：每个业务实体一行，手动输入/粘贴表单 ID；
3. "读取表单"：后端用加密密钥调明道云 API 拉取表单结构（字段名/控件ID/类型/选项）→ 自动匹配（按字段中文名/别名相似度打分 + 置信度）；
4. 页面展示"本地字段 ↔ 表单字段"对照表，逐行可手动调整；未识别字段高亮；选项值/关联关系自动解析、特殊情况可覆盖；
5. 保存写入 `hap_mapping`/`hap_field_mapping`；同步引擎从数据库读映射；未配置实体=同步禁用并提示。

安全要求：
- 密钥仅后端可见；所有明道云调用在后端完成；
- API 返回脱敏（只回 `configured/updated_at`，不回任何密钥字符）；
- `.env` 中的历史密钥不随代码分发（部署文档提示轮换）；设置页访问沿用现有 API Key 鉴权。

## 7. 同步引擎（通用化）

- 实体注册表（代码内）：每实体声明本地模型、字段定义（中文名/别名/类型）、默认同步方向；
- 映射解析器：从 `hap_mapping`/`hap_field_mapping` 加载；无映射跳过；
- 通用 pull（按 `hap_row_id` upsert，全量/增量可配）、通用 push（按 `sync_status` 扫描，create/update/delete）；
- 选项键/关联字段/日期类型转换沿用现有 `sync_service` 逻辑，从映射读取；
- 触发：手动（拉取/推送/全量）+ 定时（间隔参数）+ 排产确认后推送；
- 回写字段清单（工单表单）：投料量、成品率、放量比、单件周期、采用通量、瓶颈工序、批量周期、交期字段、最晚投料日、排产日期、排产优先级等，具体字段以映射页配置为准。

## 10. 验收与测试（SDD + MPS Check-list）

**MPS 业务逻辑 Check-list（必须交付）**：
- 从 V1.6 逻辑书、V1.7 清单、工单样本、mps-web 行为中**逐条**提取业务规则，形成编号清单：`规则编号 | 规则描述 | 来源(章节/列/行为) | 预期结果 | 测试用例 | 状态`；
- 每条规则编制至少一个测试用例（单元：核算公式；集成：排产/同步/双库流转）；测试与清单一一对应、可追溯；
- 覆盖范围：周期类（单件/加急/批量/交付）、成品率与放量比、投料量与产出校核、通量与瓶颈、DB/WB 分流与折算、爬坡、周负荷与判定、优先级引擎、排产约束（产能/齐套/串行/分部件）、同步映射、双库一致性；
- 基线：复刻 mps-web 校验集（47 项）为 pytest，官方算例数字一致（如 M02-2D：T单件=6、投料 1052、批量周期 16、交付 17、最晚投料 12/14 等）；
- 疑点参数化：WB 自动通量 12000/20000、批量项取整、订单缓冲 1 天、爬坡触发、BOM 唯一数据源——按 `system_param` 参数实现并逐项测试两档取值，待业务确认后定默认。

**验收标准**：
1. 核算：官方算例逐项通过；check-list 全量用例通过
2. 排产：确定性基准与 mps-web 输出一致；GA/CP-SAT 硬约束零违反且 KPI 不劣于基准
3. 映射：读表单→自动匹配→手动调整→保存→拉取/推送往返数据一致；API 永不回显密钥
4. 双库：同一套测试在 SQLite 与 PostgreSQL 均通过；纯本地（未配置映射）全功能可用
5. 前端：六视图 + 映射页关键路径走查

## 11. 风险与开放问题

| 风险/疑点 | 应对 |

| MPS 文档内部不一致（WB 通量、取整、缓冲、爬坡触发、BOM 源） | 参数化 + 双档测试；待业务确认后定默认，不改 MPS 文档 |
